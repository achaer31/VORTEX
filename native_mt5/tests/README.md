# Synthetic Python/native parity fixtures

These tools compare the native signal core against the unchanged `research_v02/vortex_v02/engines.py` and its H4 aggregation. They do not contact MT5 or a broker, access an account, backtest fills, calculate profit, or approve strategy deployment. Generator and comparator tests are Python tests; copying expected outputs in a comparator unit test is not an actual native run.

From the repository root, using its Python research dependencies:

```sh
python native_mt5/tests/parity_fixtures.py /path/outside/repository/native-parity-fixtures-v1
python -m unittest discover -s native_mt5/tests -p 'test_parity_tools.py' -v
```

The output directory must be new and outside the repository. It contains only deterministic synthetic data. Use the complete flat input set `fixture_kind.txt`, `cases.csv`, each case's `_M5.csv`, `_M15.csv`, `_H1.csv`, `_external.csv`, and `mode_cases.csv` with the separately compiled `VortexParityCheck.mq5` harness. Keep the Python expected CSVs and `python_reference_manifest.json` for comparison. H4 is derived from four exact H1 bars by each implementation; no H4 input CSV is supplied.

Every base scenario starts with 960 H1 bars (240 H4), 640 M15 bars, and 960 M5 bars. Cases cover deterministic rising/falling oscillations and strict pivots, quiet/wild/recovery volatility, zero ATR, gaps, initially absent HTF context, invalid calendar/macro/session or spread, and absent external context. Gaps remain absent and cause context age checks to fail. Session levels are generated by the frozen Python `session_context` only as declared synthetic inputs. No news coverage or macro-feed provenance is claimed. Twenty-two independent mode cases cover LONG/SHORT across NORMAL/AGGRESSIVE/EXTREME and invalid/boundary votes. The fixed trend data also produces LONG and SHORT outputs, without searching for profitable trades or changing the reference rules.

CSV headers are the contract shared with the native harness. All timestamps are integer UTC epochs; all flags are `0` or `1`. Missing numeric values are empty strings. A missing HTF timestamp must be blank, and its alignment must be blank; alignment `0` on an existing but unaligned/warmup context is a real value. Empty `external.csv` means a header with no data rows and mandatory context invalidation. Price/indicator fields preserve 17 significant digits.

After an actual separately verified native run, copy its private result folder and compare:

```sh
python native_mt5/tests/compare_parity.py --fixtures /path/to/native-parity-fixtures-v1 --actual /path/to/native-results --report /path/to/parity-report.json
```

The comparator requires the native manifest to declare the expected versions, completed computation, exact case/row counts, no error, and no self-asserted parity or strategy approval. Reference CSV hashes and hashes of the currently installed frozen Python sources must match the generation manifest. Missing/duplicate/reordered rows, schema drift, malformed numbers, and missing-versus-zero values fail comparison. Booleans, directions, modes, timestamps, and reasons compare exactly. Floating outputs use absolute tolerance `1e-7` and relative tolerance `1e-10`; no tolerance applies to an invalid flag or mode change.

`PARITY_PASS` only means the supplied numerical artifacts agree within that contract. CSV manifests and hashes establish consistency, not cryptographic proof that MetaEditor executed the source. Record source hashes, actual compiler results, fixture transfer identity and observed native completion separately. It does not establish market-data validity, predictive edge, costs, latency, autonomous recovery, or GO. Generated fixtures and raw native outputs remain outside Git; only these tools, tests and documentation are versioned.
